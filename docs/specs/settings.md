# 설정

사이드바의 ⚙로 여는 패널. 일반 탭과 헤이즐 탭 둘이다.

- 이 문서 — 설정 패널의 항목과 동작
- 헤이즐 내보내기·생일이 왜 설정에 있는가 — `docs/companion-persona.md` §3 "거부", "직무에 필요한 것만 묻는다"

## 동작

### 자리

- 다른 도구처럼 콘텐츠 영역에 열린다. 방은 위에 그대로 있다
- ⚙ 버튼이 사이드바 항목과 같은 선택 표시를 받는다. 설정을 여는 동안 다른 항목은 선택이 풀린다
- 설정 화면은 헤이즐의 목소리가 아니라 중립 UI 언어다(페르소나 §5 "목소리의 경계")
- 모든 문구는 번역 키다

### 일반 탭

- **창 크기** — 셸 창 크기 세 단계(1280×720 / 1600×900 / 1920×1080). 고르면 바로 바뀌고 가운데로 온다
- **음량** — 전체 음량. 끄는 동안 바로 들리고, 놓을 때 저장한다
- **알람 소리** — 소리 세트와 미리 듣기
- **Voyage 종료** — 기록을 저장하고 앱을 끝낸다. 헤이즐을 바탕화면에서 내보내면 시메지 우클릭 메뉴가 없어지므로 이 버튼이 종료 경로가 된다

### 헤이즐 탭

- **호칭** — 헤이즐이 부르는 이름. 온보딩에서 받은 값을 고친다. 비우면 부르지 않는다. 최대 12자(온보딩과 같다)
- **목소리 음량** — 헤이즐 발화음 음량
- **생일** — 월과 일만 받는다. 연도는 받지 않는다
  - 헤이즐은 나이가 필요 없고, 사적인 것을 캐지 않는다(페르소나 §3)
  - 비워둘 수 있다. 비우면 없는 것이다
  - 헤이즐은 이 칸의 존재를 말하지 않는다(페르소나 §3)
  - 생일 이벤트(그날의 대사)는 이 문서 범위 밖이다
- **바탕화면에 헤이즐 두기** — 스위치. 아래 "내보내기"

### 내보내기 — 바탕화면에서만 물러난다 (2026-10-02 유저 결정)

- 스위치를 끄면 시메지만 꺼진다
- 방·쪽지·헤이즐 부르기·하루 판정·로어 해금은 그대로다
- 끄면 헤이즐이 말없이 가장 가까운 화면 가장자리로 걸어가 밖으로 나간다
- 켜면 오른쪽 아래 가장자리에서 걸어 들어와 평소로 돌아간다. 처음 왔던 자리와 같은 쪽이다
- 꺼진 동안 셸을 닫으면 앱이 끝난다. 남는 창이 없기 때문이다

### 내보내기 — 방으로 들어간다 (2026-10-02 유저 결정)

- 바탕화면에서 나간 헤이즐은 셸 상단의 자기 방으로 들어가 거기서 지낸다
- 헤이즐은 한 번에 한 곳에만 있다. 바탕화면에 있는 동안은 방에 없고, 방에 있는 동안은 바탕화면에 없다
- 이유: 내보낸 헤이즐이 어디에도 없으면 "한 번에 한 곳"이 끊긴다. 방에 들어가 있으면 거부권은 진짜인 채로(바탕화면에서는 실제로 사라진다) "쫓아냈다"가 아니라 "자기 방에 들어갔다"로 읽힌다
- **오가기** — 바탕화면 가장자리로 나간 뒤 방의 왼쪽 가장자리에서 걸어 들어와 제자리에 선다
- 돌아올 때는 방의 왼쪽으로 걸어 나간 뒤 바탕화면 오른쪽 아래에서 들어온다
- 셸이 닫혀 있으면 방 쪽 걸음은 보이지 않으니 걷지 않고 바로 서거나 바로 나간다
- 내보낸 채로 앱을 켜면 헤이즐은 처음부터 방의 제자리에 있다
- **지내는 규칙은 바탕화면과 같다** — 평소엔 숨·깜빡임만, 가끔 자기 일(읽기·도토리 묻기·방 안 걷기). 간격도 같다
- 방 안 걷기는 창문부터 트렁크 앞까지의 바닥에서만 한다
- 제자리는 책장과 책상 사이다
- **쪽지** — 쪽지가 꽂히면 그 자리에서 수첩에 적는다. 다른 일을 하는 중이면 생략한다(시메지와 같다)
- **부르기** — 방을 누르거나 홈에서 판정하면, 대화 모드에서 걸어 들어오지 않고 방 안 그 자리에 서 있는 채로 시작한다
- 대화가 끝나도 나가지 않는다. 대화 안에서 옮겨 간 자리(판정 뒤 트렁크 앞 등)에 그대로 남는다
- **집중 세션** — 램프가 켜지고 헤이즐은 평소처럼 지낸다. 쪽지는 꽂히지 않는다(기존 방 규칙)
- 방은 배너 높이(160)라 헤이즐은 리그를 0.55배로 줄여 그린다. 아트를 의뢰할 때 "작은 크기에서도 읽히는 포즈"가 요구사항에 더해진다
- 꺼진 채로 앱을 켜면 셸이 열리고 바탕화면에는 헤이즐이 없다
- 기록은 그대로 남는다(페르소나 §3 "내보내도 수첩 기록은 남는다")
- 다시 켤 수 있다. 영구 상실이 아니다(페르소나 §3, §4 금지 4번)
- ⚠️ 이유: 바탕화면에 무언가 떠 있는 것이 싫은 유저도 판정과 로어를 이어갈 수 있다. 페르소나의 "시메지가 실제로 꺼진다"와 정확히 같다
- 검토하고 고르지 않은 것
  - 헤이즐이 완전히 떠나 판정까지 멈추는 것 — 판정을 헤이즐에게만 건네기로 해서 판정과 해금이 함께 멈춘다
  - 대화 모드에서 한 마디 하고 떠나는 것 — 떠나는 말은 무엇을 써도 미안함을 남기기 쉽다(금지 2·4번 근처)
  - 즉시 사라지고 나타나는 것 — 기능을 끄는 느낌이고 헤이즐이 물러나는 것으로 읽히지 않는다

### 뺀 항목 (2026-10-02 유저 결정)

- **창 모드(전체화면·테두리 없음)** — 셸은 짧게 열고 닫는 창이고, 전체화면이면 바탕화면의 헤이즐을 가린다
- **항상 위에** — 상주하는 역할은 시메지가 맡았다
- **프레임 제한** — 화면에서 뺀다. 저장된 값(기본 60)은 그대로 쓴다
- **HUD 위치 초기화** — HUD가 셸에 없다
- **비포커스 프레임 제한** — 시메지 때문에 30 아래로 내려가지 않아(`screen.gd`의 `SHIMEJI_MIN_FPS`) 5/10/15가 30과 같았다
- 창 모드와 항상 위에는 이미 켜 둔 저장 파일이 있으면 끌 길이 없어진다. 그래서 저장된 값과 상관없이 셸은 늘 일반 창, 항상 위 꺼짐으로 뜬다

## 범위 아님

- 생일 이벤트 대사. 페르소나 §7 "시간 이벤트" 작업이다
- 타이머 길이 같은 도구별 설정. 각 도구 안에 있다
- 언어 선택
- 시메지 우클릭 메뉴에 설정 항목을 더하는 것
- 옛 월드의 설정 패널(`scenes/option/OptionPanel.tscn`)을 지우는 것. 월드 코드 삭제가 보류 중이라 같이 둔다(CLAUDE.md)

## 메커니즘 영향

### 저장 (2026-10-02 합의)

- `AppSettings`에 두 필드가 는다. 저장 파일은 `save.json`의 `settings` 그대로다
  - `birthday: String` — `"MM-DD"`. 빈 문자열이면 없음. 호칭과 같은 자리라 페르소나 §11의 "생일의 저장 위치"가 여기서 정해진다
  - `hazel_on_desktop: bool` — 기본 `true`
- 저장 정책은 전역 설정과 같은 save-on-change(`AppSettings.changed` → `Save`)다
- `window_mode`·`always_on_top`·`fps_unfocused`·`hud_*` 필드는 지우지 않는다. 읽지 않을 뿐이다

### 셸

- 설정 패널은 `MainShell.CONTENT_SCENES`의 6번이다
- 사이드바 내비게이션 묶음에 ⚙ 버튼을 6번으로 더한다. NavList의 0~5는 그대로라 온보딩과 시메지 메뉴의 인덱스가 안 바뀐다
- `Screen.apply_window_mode`는 저장값을 보지 않고 늘 일반 창이다. `apply_always_on_top`은 늘 끈다

### 시메지 (2차)

- 시메지 루트가 `AppSettings.changed`를 듣고 `hazel_on_desktop`이 바뀌면 나가거나 들어온다
- 바탕화면 자리는 `HERE` / `LEAVING` / `AWAY` / `ARRIVING` 넷이다
- 나가는 동안·나가 있는 동안은 "자리 비움"이다. 바탕화면의 만지기·메뉴·자기 일·쪽지 적기가 멈춘다
- 헤이즐 부르기는 나가 있는 동안에도 된다. 걷는 중이면 무시한다
- 나가 있는 동안 셸의 닫기는 숨기기가 아니라 종료(`Save.quit_game`)다
- 나가고 들어오는 중에 스위치가 다시 바뀌면, 하던 걸음을 마치고 그때의 값으로 다시 맞춘다. 온보딩·부르기·들기·떨어지기가 끝나는 자리에서도 다시 맞춘다
- 나가고 들어오는 걸음은 120px/s다. 평소 걷기(46)보다 빠르다 — 떠나는 데 오래 걸리면 미련으로 읽힌다

### 방 안의 헤이즐

- `scripts/room/room_hazel.gd`. 배너가 방의 자식으로 붙인다. `MainShell.room_hazel()`로 시메지 루트가 찾는다
- 몸은 `shimeji_view.gd`를 0.55배로 쓴다. 방 좌표로 서고, 방(`clip_contents`)이 잘라내 가장자리 밖은 안 보인다
- 자기 일 간격·걷기 시간은 시메지와 같은 값을 옮겨 적었다. `shimeji_root.gd`를 preload 하면 셸 씬과 순환하기 때문이다. 바꿀 때 둘 다 바꾼다
- 시메지 루트가 나간 뒤 `enter`, 들어오기 전 `leave`를 부른다. `leave`는 방에서 걸어 나가는 걸 기다린다
- 부르기 재생기는 `start(..., room_x)`로 시작 자리를 받는다. 대화 모드의 `place_at`으로 그 자리에 세운다. 방 좌표와 화면 좌표는 `hazel_room.gd`의 `to_screen_x`/`to_room_x`로 바꾼다
- 끝난 자리는 재생기의 `end_room_x`로 돌려받아 방 안의 헤이즐을 거기 세운다
- 부르기 동안 방 안의 헤이즐은 자기 일을 멈춘다(`paused`)
