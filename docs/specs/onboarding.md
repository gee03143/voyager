# 온보딩

첫 실행에서 헤이즐이 바탕화면에 나타나 자기를 소개하고 다이어리 셸로 인계하는 짧은 시퀀스.

## 동작

### 자리
- 온보딩은 시메지에서 재생된다
- 첫 실행에서 다이어리 셸은 열리지 않는다
- 별도 인트로 화면을 띄우지 않는다
- 헤이즐은 화면에 이미 있는 상태로 시작한다. 등장 연출을 두지 않는다
- 등장 연출을 빼는 이유는 로어다. 헤이즐은 여기 사는 이웃이지 방금 설치된 것이 아니다
- 헤이즐은 온보딩의 존재를 대사로 언급하지 않는다

### 트리거
- 첫 실행에서 한 번만 재생된다
- 완료된 뒤에는 어떤 경로로도 다시 재생되지 않는다
- 이미 활동 기록이 있는 저장 파일은 완료된 것으로 간주한다

### 흐름
- 헤이즐이 네 문장을 차례로 말한다
- 문장은 시메지 말풍선에 뜬다
- 앞의 세 문장에는 선택지가 없다
- 마지막 문장에만 선택지가 붙는다
- 선택지는 두 개다

### 진행
- 문장이 완성되면 잠깐 머문 뒤 다음 문장으로 자동으로 넘어간다
- 머무는 시간은 글자 수에 비례한다. 초안값은 0.8초 + 글자당 30ms
- 말풍선을 클릭하면 타이핑 중인 문장이 즉시 완성된다
- 완성된 문장을 클릭하면 머무는 시간을 건너뛰고 바로 다음 문장으로 넘어간다
- 건너뛰기 버튼은 두지 않는다. 네 문장이라 되돌릴 것이 없다
- 재생 중에는 시메지가 자기 일을 하지 않는다. 생리적 움직임만 돈다

### 선택
- `할 일 적기`를 고르면 다이어리 셸이 열리고 할일 탭으로 간다
- 셸이 열린 뒤로는 배너가 발화를 받는다. 시메지 말풍선은 닫힌다
- 이 인계가 두 층이 있다는 것을 설명 없이 동작으로 가르친다
- `나중에 하기`를 고르면 헤이즐이 물러서는 한 줄을 말하고 말풍선을 닫는다
- 물러섬 문장은 기존 `COMPANION_STAND_START`를 쓴다
- `나중에 하기`를 골라도 셸은 열리지 않는다. 시메지만 남는다
- 어느 쪽을 골라도 온보딩은 완료로 기록된다

### 통로 알리기
- 온보딩이 끝난 뒤 첫 혼잣말이 우클릭 통로를 한 번 알린다
- 어느 선택지를 골랐든 나온다
- 한 번만 나오고 이후 혼잣말 풀에는 섞이지 않는다
- 이 문장이 없으면 `나중에 하기`를 고른 유저는 도구를 여는 법을 모른 채 남는다
- 혼잣말 시스템 자체는 시메지 spec 관할이다. 여기는 이 한 문장만 정한다

### 중단
- 마지막 선택 전에 앱을 끄면 다음 실행에서 처음부터 다시 재생된다
- 재생 도중에는 시메지의 다른 반응이 말풍선을 갈아치우지 않는다

### 대사 초안 — 승인 필요
페르소나 §10의 기준 샘플을 그대로 따른다.

| 키 | ko | en |
|---|---|---|
| `COMPANION_ONBOARD_1` | 안녕. 나는 헤이즐이야. | Hi. I'm Hazel. |
| `COMPANION_ONBOARD_2` | 여기 살아. 앞으로 이웃이네. | I live here. Neighbors now. |
| `COMPANION_ONBOARD_3` | 마침 겨울 준비 중이었어. | Was just getting ready for winter. |
| `COMPANION_ONBOARD_4` | 오늘 할 일 하나 적어볼까? 나도 하나 할게. | Want to write one task? I'll do one too. |
| `COMPANION_ONBOARD_OPT_WRITE` | 할 일 적기 | Write a task |
| `COMPANION_ONBOARD_OPT_LATER` | 나중에 하기 | Maybe later |
| `COMPANION_ONBOARD_DOOR` | 필요한 건 오른쪽 눌러서 꺼내. | Everything's over here. Right-click. |

`COMPANION_ONBOARD_DOOR`의 `꺼내`는 로어와 붙는다. 헤이즐은 묻어둔 걸 꺼내는 존재다.

규격 검증(§5·§0 기준): 한국어 최장 24자, 느낌표 0, 2인칭 0, 3인칭 자칭 0. 1인칭은 자기 쪽 문장에서만 쓰였다. 로어는 3번 문장에서 설명 없이 흘린다.

## 범위 아님
- 시메지 셸 자체. 투명 창·상주·클릭 반응·행동 목록은 시메지 spec 관할
- 혼잣말 시스템. 풀 구성·빈도·해금은 시메지 spec 관할
- 우클릭 메뉴의 구성. 어떤 도구가 어떤 순서로 뜨는지는 시메지 spec 관할
- 시메지 등장 애니메이션
- 도구 투어. 할일 외의 도구는 온보딩에서 언급하지 않는다
- 호칭·생일 입력. §3에 따라 헤이즐은 묻지 않는다
- 친밀도, 만난 날 수, 첫 만난 날 저장
- 아바타 포즈·표정 변화. 온보딩 동안은 기본 대기 포즈뿐이다
- 온보딩 다시 보기 메뉴
- 건너뛰기 버튼
- `COMPANION_TALK_FIRST` 교체. 첫날 대화 오프너는 지금 문장 그대로 둔다
- 온보딩 전용 효과음. 기존 발화음을 쓴다

## 메커니즘 영향
- `AppSettings`에 `onboarded: bool`을 추가한다
- 저장 위치는 `save.json`의 `settings`다
- 저장 시점은 전역 설정 정책대로 save-on-change다
- `save.json`의 `VERSION`은 올리지 않는다. 키가 없는 기존 파일은 기본값으로 읽힌다
- 로드 시 `onboarded` 키가 없고 활동 기록이 비어 있지 않으면 `true`로 채운다
- 첫 실행 진입점이 바뀐다. `onboarded`가 거짓이면 다이어리 셸을 열지 않고 시메지만 띄운다
- 시메지 말풍선에 문장 큐를 둔다. 반응 하나가 아니라 여러 문장을 받아 차례로 재생한다
- 문장 큐는 배너와 같은 계약을 쓴다. 두 뷰가 같은 연출 규격을 공유한다
- 문장 큐는 온보딩 전용이 아니다. 이후 다른 반응도 여러 문장으로 말할 수 있게 된다
- 시메지가 다이어리 셸 열기를 요청하는 시그널이 필요하다
- `CompanionEngine`에 온보딩 시퀀스 표를 추가한다. 대화 노드 표와 같은 자리에 둔다
- 신규 번역 키 `COMPANION_ONBOARD_*`를 추가한다
- 저장 파일 구성은 바뀌지 않는다
- 구현 후 `docs/specs/companion-banner-typing.md`에 문장 큐 항목을 더한다

## 선행 조건
- 시메지 셸이 먼저 있어야 한다. 투명 창, 리그 표시, 말풍선이 그것이다
- 이 spec은 시메지 셸 spec이 확정된 뒤에 구현에 들어간다
