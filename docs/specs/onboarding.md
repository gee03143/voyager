# 온보딩

첫 실행에서 헤이즐이 바탕화면으로 찾아와 집사로 부임하고, 유저에게 도구를 소개한 뒤 시메지로 자리 잡는 시퀀스.

⚠️ **2026-09-28 전면 교체.** 이전 판은 셸 오버레이 + 격식체 7비트 기준이었다. 이번 판은 `ArrivalProto` 프로토타입(삭제됨, git 히스토리)에서 확인한 결과를 옮긴 것이다.

⚠️ **셸 상단의 배너 자리는 헤이즐의 방이다(`docs/specs/hazel-room.md`).** 이 문서의 "배너"는 그 방과 쪽지를 품은 노드(`CompanionBanner`)를 가리킨다.

- 헤이즐이 누구인가 — `docs/companion-persona.md`
- 대사 전문 — `docs/companion-butler-draft.md`
- 이 문서 — **어떻게 동작하는가**

## 동작

### 톤

- 코지하다. 차분하고 유머가 조금 섞인다
- 흔들림·암전·크게 찍히기 같은 연출은 쓰지 않는다
- 웃음은 간격과 절제에서 나온다
- 헤이즐은 해요체를 쓰는 초짜 집사다. 말은 서툴러도 손은 확실하다

### 무대

- 무대가 둘이다. **바탕화면**과 **셸 창**
- 1비트는 바탕화면에서 시작해 셸 창으로 넘어간다
- 2~4비트는 셸 창에서 진행된다
- 5비트에서 헤이즐이 바탕화면으로 돌아가 시메지가 된다

### 바탕화면 무대

- 시메지 창이 무대가 된다. 온보딩 동안만 넓힌다
- 넓힌 창은 투명하다. 그려진 픽셀만 클릭을 받는다
- 헤이즐과 트렁크, 말풍선, 선택지, 카드가 이 창 안에 그려진다
- 1비트에서는 넓힌 창(720×440)을 화면 오른쪽 아래에 붙여 두고 **창 안에서** 헤이즐이 걷는다. 창 오른쪽 가장자리가 곧 화면 가장자리라 트렁크가 화면 밖에서 들어오는 것처럼 보인다
- 5비트에서는 시메지 크기 창이 헤이즐과 함께 움직인다. 지금 시메지의 걷기와 같은 방식이다
- 헤이즐이 셸 창으로 들어간 뒤(2~4비트)에는 바탕화면에 헤이즐이 없다. 헤이즐은 한 번에 한 곳에만 있다
- 온보딩이 끝나면 시메지 크기로 돌아온다

### 셸 창의 대화 모드

- 셸 창에는 도구 모드와 대화 모드가 있다
- 대화 모드는 사이드바와 배너까지 덮고 창 전체를 쓴다
- 대화 모드의 바탕은 헤이즐의 방이다. 셸 상단의 방을 창 크기로 확대한 것이다
- 온보딩의 방은 **헤이즐이 오기 전의 방**이다. 트렁크도 수첩도 없다
- 4비트에서 대화 모드의 바탕이 걷히고 도구 모드가 드러난다
- 4비트에 드러난 셸 상단의 방도 헤이즐이 오기 전 모습이다. 쪽지는 꽂혀 있지 않다
- 5비트에서 방이 다시 깔린다
- 바탕이 걷힌 뒤에도 헤이즐은 셸 위의 층에 남아 사이드바를 가리킨다
- ⚠️ 헤이즐이 UI 를 너무 가리면 셸 창 바깥(바탕화면)에서 가리키는 방식으로 옮긴다

### 트리거

- 첫 실행에서 한 번만 재생된다
- `Save.settings.onboarded`가 거짓일 때 재생한다
- 완료된 뒤에는 어떤 경로로도 다시 재생되지 않는다
- 이미 활동 기록이 있는 저장 파일은 완료된 것으로 간주한다
- 헤이즐은 온보딩의 존재를 대사로 언급하지 않는다

### 흐름

- 비트가 다섯이다. 부임 / 이유 / 이름 / 짐 풀기 / 물러남
- **모든 선택지가 같은 지점으로 수렴한다.** 선택지가 바꾸는 것은 헤이즐의 반응 한 묶음뿐이다
- 반응은 선택지마다 다르다
- 원점으로 되돌아오는 선택지는 두지 않는다

### 1비트 · 부임

- 앱을 켜면 한동안 아무 일도 없다
- 화면 오른쪽 아래 가장자리에서 트렁크가 끄는 소리와 함께 밀려 들어온다
- 트렁크 뒤에서 헤이즐이 나와 둘러보고, 화면 쪽으로 걸어와 화면 유리를 안쪽에서 두드린다
- 이 비트 동안 헤이즐의 이름표는 `???`다
- 유저가 열어주면 셸 창이 대화 모드로 열리고, 헤이즐이 트렁크를 끌고 창 안으로 들어간다
  - 셸은 바탕화면 무대와 **같은 모니터**의 가운데에 열린다. `Screen`은 셸 자신의 모니터 기준으로 가운데에 두므로, 모니터가 여럿이면 엇갈렸다(2026-10-01 유저 보고)
  - 바탕화면 무대의 왼쪽 가장자리로 걸어 나간 뒤, 셸 대화 모드의 왼쪽 가장자리에서 트렁크를 끌고 들어온다
  - 셸이 열려도 헤이즐이 걸어 들어오기 전까지 대화 모드는 비어 있다. 헤이즐은 한 번에 한 곳에만 있다
- 열어주는 방법은 둘이다. 선택지 `(열어준다)`, 또는 바탕화면의 헤이즐을 직접 누르기
- 이 비트의 끝에서 헤이즐이 이름을 밝히고 이름표가 `헤이즐`로 뒤집힌다

### 2비트 · 이유

- 헤이즐이 트렁크에서 앞치마와 수첩을 꺼낸다
- 왜 왔는지와 여기서 무엇을 할지를 말한다
- 헤이즐은 날들을 모으는 단체의 수습이다. 단체의 이름은 부르지 않는다
- ⚠️ 수습의 졸업 조건을 유저의 행동에 걸지 않는다. 유저가 헤이즐을 위해 앱을 열게 되면 압박이 된다

### 3비트 · 이름

- 헤이즐이 호칭을 묻는다
- 유저는 입력 칸에 적거나 `...그건 나중에요.`를 고른다
- ⚠️ 입력 칸 옆 버튼은 포커스를 가져가지 않는다. Windows는 조합 중 클릭이 확정 문자보다 먼저 배달되어, 버튼이 포커스를 가져가면 한글 마지막 글자가 사라졌다(2026-10-01 유저 보고, `docs/architecture/ime-commit-guard.md`)
- 적으면 헤이즐이 받아 적고 그 이름을 처음 부른다
- 비워두면 부르지 않는다. 다시 묻지 않는다

### 4비트 · 짐 풀기

- 대화 모드의 바탕이 걷힌 뒤 헤이즐이 트렁크를 끌고 셸의 오른쪽 아래로 자리를 옮긴다. 사이드바와 도구 목록을 덜 가리는 곳이다
- 헤이즐이 트렁크에서 도구를 하나씩 꺼낸다. 할 일 / 습관 / 타이머 / 일지 / 기록
- 꺼낸 도구는 트렁크에서 사이드바의 그 항목으로 날아가 스며든다
- 하나를 꺼낼 때마다 왼팔을 들어 사이드바의 그 항목을 가리키고, 항목에 테를 두른 채 한 줄로 소개한다
- 헤이즐은 **무엇을 해주는지와 어디 뒀는지만** 말한다. 조작법은 말하지 않는다
- 소개가 끝나면 헤이즐이 할 일을 한 번 권한다
- 할 일 도구가 열리기 직전에 기본 그룹에 예시 할 일 `할 일 추가하기` 하나가 들어간다
- 예시 할 일은 유저가 적든 적지 않든 들어간다
- 예시 할 일은 도구의 것이다. 헤이즐의 말이 아니라 중립 UI 언어다
- 할 일 도구가 실제로 열린다. 유저가 직접 적는다
- 헤이즐은 유저가 적는 동안 말을 걸지 않는다
- 할 일 도구가 열리는 동안 헤이즐 곁에 선택지 `나중에 할게요` 하나가 뜬다. 할 일 도구에 버튼을 더하지 않는다
- 유저가 한 줄 적으면 선택지가 거둬지고 헤이즐이 반응한다
- `나중에 할게요`를 누르면 헤이즐이 물러선다. 다시 권하지 않는다

### 5비트 · 물러남

- 대화 모드의 바탕(방)이 다시 깔린다
- 헤이즐이 빈 트렁크를 방 구석으로 밀어 놓는다. 한 걸음 물러나 보고, 반 뼘 옮기고, 다시 본다
- 이 트렁크가 방의 트렁크가 된다. 셸 상단의 방에도 이때부터 트렁크가 있다
- 헤이즐이 밖에 있겠다고 알리고, 유저가 마지막 인사를 고른다
- 헤이즐이 셸 창 가장자리로 걸어 나간다. 셸에서 사라진다
- 대화 모드가 걷히고 셸 상단의 방이 드러난다. 구석에 헤이즐의 트렁크가 있다
- 같은 자리의 바탕화면에 헤이즐이 나타나 바닥으로 내려앉는다. 이제 시메지다
- 시메지는 1비트에서 트렁크가 들어왔던 화면 오른쪽 아래로 걸어간다
- 자리에서 수첩에 첫날을 적는다. 대사는 없다
- 셸은 닫히지 않는다. 할 일 화면이 열린 채 남는다
- 첫날을 적고 나면 방의 책상에 오늘의 수첩이 펼쳐지고 쪽지가 꽂힌다
- **끝나는 화면을 두지 않는다.** `완료` 버튼도 축하 문구도 없다
- 시메지의 자기 일이 여기서 다시 돈다
- 시메지가 자리에 도착한 순간 `onboarded`가 참이 된다

### 줄

- 헤이즐의 말은 머리 위 말풍선에 **지금 하는 말 하나만** 뜬다
- 말풍선 왼쪽 위에 이름표가 걸린다
- 유저의 말(선택한 선택지)은 조용히 떠올랐다 사라진다
- 내레이터는 작은 기울임 명조로 조용히 덧붙인다. 사실만 말하고 드물게 쓴다
- 셸이 드러난 뒤(4비트부터)와 바탕화면에서는 내레이터 뒤에 종이를 받친다. 뒤의 글자나 배경과 겹쳐 읽히지 않기 때문이다
- 지문은 글로 쓰지 않는다. 헤이즐의 동작과 소품으로 보여준다
- 소리는 효과음으로만 낸다. 소리 글자(`드르륵……`, `똑.` 같은)는 화면에 띄우지 않는다
- 글자가 뜨던 시간만큼은 기다림으로 남겨 박자를 지킨다

### 효과음

- 효과음은 동작과 소품에 붙는다. 대사와 내레이터에는 붙지 않는다
- 트렁크를 끌고 밀 때 끄는 소리가 난다. 걷는 동안 이어지고 멈추면 잦아든다
- 두드릴 때마다 노크 한 번이 난다
- 문턱에서 발을 털 때마다 발소리가 난다
- 인사(꾸벅)에 옷 스치는 소리가 난다
- 트렁크를 열 때 걸쇠 소리, 마지막 짐을 꺼내고 닫을 때 뚜껑 소리가 난다
- 앞치마를 두를 때 천 소리, 수첩을 꺼낼 때 책 놓는 소리, 수첩을 펼 때 책 여는 소리가 난다
- 다음 장으로 넘길 때 책장 소리가 난다
- 연필 깎기·줄 긋기는 `슥` 소리 두 번, 적기는 `사각` 소리 여러 번이다. 바탕화면의 첫날 적기도 같다
- 도구가 사이드바로 날아갈 때 작은 튕김 소리가 난다
- 바탕화면에 내려앉을 때 부드러운 착지 소리가 난다
- 걷기·뛰기에는 소리를 붙이지 않는다. 너무 잦다

### 표정

- 헤이즐의 대사마다 표정이 붙는다
- 표정은 미소 / 차분 / 당황 / 생각 / 놀람 / 쑥스러움 여섯에 기본을 더한 일곱이다
- 당황에는 땀방울, 쑥스러움에는 홍조가 얹힌다
- 기쁨은 대사가 아니라 몸으로 낸다

### 진행

- 타이핑 중인 말풍선을 누르면 즉시 완성된다
- 완성된 말풍선을 누르면 머무는 시간을 건너뛴다
- 선택지는 그 비트의 마지막 줄이 완성된 뒤에 나타난다
- 건너뛰기 버튼은 두지 않는다

### 저장되는 것

- 호칭은 `AppSettings.nickname`에 들어간다. 비우면 빈 문자열이다
- 호칭은 3비트에서 유저가 답한 순간 저장한다. 저장하는 쪽은 재생기다
- 할 일은 유저가 할 일 도구에서 직접 적은 것이 그대로 남는다
- 예시 할 일 `할 일 추가하기`가 기본 그룹(`Save.todo_groups[0]`)에 `Todo` 하나로 남는다. 마감일은 없다
- 유저가 적지 않고 넘어가도 목록은 비지 않는다. 예시 할 일이 남기 때문이다
- 예시 할 일을 체크하면 평소의 할 일 완료 반응이 나온다. 온보딩이 따로 처리하지 않는다
- ⚠️ 이전 판은 비워두면 헤이즐이 `아무것도 안 하기`를 대신 적었다. 헤이즐이 유저의 할 일 목록에 손대지 않도록 예시 할 일로 바꿨다
- 완료 시 `onboarded`가 참이 된다

### 중단

- 완료 전에 앱을 끄면 다음 실행에서 처음부터 다시 재생된다
- 중간 진행 상태를 저장하지 않는다
- 온보딩 중에 셸 창을 닫으면(X·Alt+F4) 온보딩이 멈춘다. 유저는 언제든 빠져나올 수 있어야 한다
  - 셸이 숨고 대화 모드가 걷힌다
  - 헤이즐은 바탕화면 시메지로 돌아온다. 만지기·메뉴·자기 일이 풀리고 방과 쪽지도 평소대로 돌아온다
  - `onboarded`는 거짓으로 남는다. 다음 실행에서 처음부터 다시 재생된다
  - 이번 실행에서 메뉴로 셸을 다시 열면 평소의 도구 화면이 나온다
  - 3비트에서 이미 저장한 호칭은 남는다. 다시 재생하면 3비트에서 새로 받는다
- 4비트에서 유저가 적은 할 일은 중단돼도 남는다. 할 일 도구가 저장하기 때문이다
- 예시 할 일이 이미 들어간 뒤에 중단되면, 다시 재생할 때 예시 할 일을 또 넣지 않는다. 같은 문구의 항목이 기본 그룹에 있으면 건너뛴다

## 범위 아님

- 대사 전문. `companion-butler-draft.md` 관할
- 페르소나 규격. `companion-persona.md` 관할
- 영어 대사. 한국어가 확정된 뒤 따로 쓴다
- 단체의 이름
- 최종 아트. 소품·트렁크·방은 도형이다
- 리그에 없는 동작의 최종 애니메이션. 인사·두드리기·가리키기·꼬리는 대체 표현으로 간다
- 배너 대사 교체. `COMPANION_*` 전량이 구 페르소나라 별도 작업이다
- 바탕화면 무대의 여러 모니터 대응. 주 모니터만 쓴다
- 생일 입력. 헤이즐은 묻지 않는다
- 친밀도, 만난 날 수, 첫 만난 날 저장
- 설정의 `내보내기` 통로
- 온보딩 다시 보기 메뉴
- 건너뛰기 버튼
- 최종 효과음. 지금은 Kenney CC0 팩에서 고른 임시 소리다(`assets/sounds/sfx/`, 라이선스 원문 동봉)
- 효과음 전용 음량 설정. 마스터 음량을 따른다
- 온보딩 밖(헤이즐 부르기·시메지 자기 일)의 효과음
- 셸 대화 모드를 온보딩 밖에서 여는 것. 헤이즐 부르기(`docs/specs/hazel-room.md`)가 맡는다

## 메커니즘 영향

### 저장

- `AppSettings`에 `onboarded: bool`을 추가한다. 기본값 거짓
- `AppSettings`에 `nickname: String`을 추가한다. 기본값 빈 문자열
- 저장 위치는 `save.json`의 `settings`다. 저장 시점은 save-on-change다
- `save.json`의 `VERSION`은 올리지 않는다. 키가 없는 기존 파일은 기본값으로 읽힌다
- 로드 시 `onboarded` 키가 없고 활동 기록이 비어 있지 않으면 참으로 채운다
  - 키가 있었는지는 `AppSettings.onboarded_in_file`이 들고 있다. 저장하지 않는 값이다
  - 판단은 `Save._ready`에서 모든 파일을 읽은 뒤, 첫 저장 전에 한다
- 저장 파일 구성은 바뀌지 않는다

### 진입점

- `shimeji_root.gd`가 시작할 때 `onboarded`를 본다
- 거짓이면 시메지를 시메지 크기로 띄우지 않고 온보딩을 시작한다
- 온보딩 동안 시메지의 자기 일 타이머와 만지기 입력, 우클릭 메뉴를 멈춘다
- `Screen.bind_shell`은 그대로 둔다
- 재생기는 끝날 때 완료인지 중단인지를 알린다. 루트는 완료일 때만 `onboarded`를 참으로 저장한다
- 완료든 중단이든 배너 복구와 시메지 복귀는 같다

### 중단의 흐름

- 재생기가 셸 창의 `close_requested`를 듣는다. 셸을 숨기는 기존 연결은 그대로 둔다
- 중단되면 대화 모드의 모든 연출 부품이 기다리지 않고 바로 돌아온다
- 선택지·입력을 기다리던 것은 "답 없음"을 받고 돌아온다
- ⚠️ 답을 기다리기 **직전에** 중단 여부를 한 번 더 본다. 선택지 판을 띄우는 한 프레임 사이에 중단되면, 중단 신호가 받을 쪽 없이 지나가 영원히 기다리게 된다(2단계 실행 확인에서 재현됨)
- ⚠️ 같은 이유로 답도 받아둔다. 답은 기다리기 전에 도착할 수 있다(판을 띄우는 한 프레임, 바탕화면 헤이즐 클릭, 할 일 적기). 신호만 쏘면 받을 쪽이 없을 때 사라진다(4단계 실행 확인에서 재현됨)
- 재생기는 선택지·입력의 답을 받은 직후마다 중단 여부를 보고, 중단이면 그 자리에서 멈춘다
- 저장처럼 흔적을 남기는 일은 항상 답을 받은 뒤에 있으므로 중단 뒤에 일어나지 않는다

### 바탕화면 무대

- 온보딩 동안 시메지 창 크기를 바꾼다. 초안값 720×440
- 시메지 창을 움직이는 코드는 지금의 걷기를 따른다
- 2~4비트 동안은 시메지 창을 **최소 크기로 줄여 모든 모니터 밖으로 옮겨둔다**
  - 처음에는 투명하게 비워둔 채 그 자리에 두었다. 셸을 그 모니터로 옮기면 셸의 선택지 자리와 겹쳐 선택지가 눌리지 않았다(2026-10-01 유저 보고)
  - 비어 있는 투명 창이 클릭을 통과시키는지는 확인하지 않았다. 통과 여부에 기대지 않고 겹칠 자리 자체를 없앤다
  - ⚠️ 주 창은 숨길 수 없다. 실행하면 엔진이 `Can't change visibility of main window`로 거부한다(2026-10-01 실행 확인)
  - 창 크기는 2×2를 줘도 64×64까지만 줄어든다(실행 확인). 그래서 크기만 줄이지 않고 화면 밖으로 옮긴다
  - 중단되면 셸이 있는 모니터로 먼저 옮긴 뒤 기본 자리를 구한다. 화면 밖에 있는 동안은 "지금 어느 모니터인가"가 엉뚱하게 잡힌다
- 끝나면 시메지 크기(280×340)와 헤이즐의 발 위치로 되돌린다

### 셸에서 바탕화면으로

- 5비트에서 헤이즐은 셸 창 **오른쪽** 가장자리로 걸어 나간다
- 그 가장자리의 대화 모드 바닥 높이를 화면 좌표로 읽는다
- 시메지 창을 그 자리에 띄운 뒤 바닥으로 떨어뜨린다. 지금 시메지의 떨어지기와 같은 중력이다
- 셸 안의 헤이즐은 대화 모드 배율, 시메지는 시메지 배율이다. 나오는 순간 크기가 바뀐다
- 시메지는 작업 영역 오른쪽 끝에서 140px 안쪽까지 걸어간다. 1비트에서 트렁크가 멈춘 자리다
- 도착한 창 위치가 곧 시메지 위치로 저장된다
- ⚠️ 셸과 시메지가 다른 모니터에 있어도 셸 가장자리 좌표에서 떨어뜨린다. 여러 모니터 동작은 범위 밖이라 확인하지 않았다

### 셸

- 셸 `Window`에 대화 모드 노드를 `MainShell`의 형제로 붙인다. 붙이는 쪽은 `shimeji_root`다
- `MainShell`은 대화 모드를 모른다
- 대화 모드의 바탕은 `hazel_room.gd`를 `fill`로 붙인 것이다. 방의 바닥 높이를 대화 모드 바닥(`FLOOR_RATIO`)에 맞춘다
- 재생기가 대화 모드의 방을 헤이즐이 오기 전 모습으로 둔다(`show_trunk`·`show_notebooks`를 끈다)
- 5비트의 트렁크 자리는 방이 트렁크를 그리는 자리다(`trunk_center_x`). 대화 모드의 트렁크 소품을 그 자리로 민다
- 대화 모드 노드는 사이드바 항목의 화면 위치를 읽어야 한다. `MainShell`에 항목 위치를 돌려주는 공개 메서드를 하나 둔다(`nav_item_rect`)
- 할 일 도구를 여는 것은 기존 `MainShell.open_tool(1)`을 쓴다

### 예시 할 일

- 온보딩이 `Save.todo_groups[0].tasks`에 `Todo` 하나를 추가한다
- 문구는 `localization/translations.csv`의 새 키에 둔다. 헤이즐의 대사가 아니므로 `ONB_*`가 아니라 `TODO_*` 접두사를 쓴다
- 추가한 뒤 `Save.save_todo()`로 바로 저장한다
- ⚠️ 할 일 도구는 열릴 때마다 목록을 다시 읽지 않는다. 처음 만들어질 때(`todo_list_view.gd`의 `_ready`) 한 번 읽는다
- 그래서 예시 할 일은 할 일 도구가 **처음 만들어지기 전에** 넣는다
- 첫 실행에서는 온보딩 전에 할 일 도구가 만들어질 경로가 없다. 셸은 홈으로 시작하고, 시메지 우클릭 메뉴는 온보딩 동안 막힌다
- 이 보장이 깨지는 경로가 생기면 할 일 도구에 목록을 다시 읽는 공개 메서드를 둔다
- `todo.json`의 구성과 `Todo`의 필드는 바뀌지 않는다

### 할 일 적기 감지

- "유저가 할 일을 한 줄 적었다"를 알리는 시그널이 지금 없다
- 할 일 행의 글자가 비어 있다가 채워지는 순간 `Companion`에 알린다
- `Companion`에 시그널 `todo_written(title)`과 알림 메서드 `notify_todo_written`을 추가한다
- 알리는 쪽은 `todo_list_view.gd`의 `_on_row_changed`다. 완료 알림(`notify_todo_completed`)과 같은 자리다
- 모델에 글자를 옮기기 직전에 "비어 있었는가"를 보고, 옮긴 뒤 채워졌으면 알린다
- 예시 할 일의 글자를 고치는 것은 적기로 치지 않는다. 비어 있던 행이 아니기 때문이다

### 배너

- 온보딩 동안 배너를 멈춘다. 숨기지는 않는다
- 멈춘 동안 쪽지를 거두고, 방은 헤이즐이 오기 전 모습(트렁크·수첩 없음)으로 그린다
- 5비트에서 헤이즐이 트렁크를 놓으면 셸 상단의 방에 트렁크만 먼저 켠다. `MainShell.hazel_room()`으로 방을 받는다
- 끝나면 배너를 되살리고 `_refresh()`를 다시 태운다. 수첩과 쪽지가 이때 돌아온다
- `CompanionBanner`에 멈춤·복구 공개 메서드를 하나 둔다(`set_suspended`)
- 멈춰 있는 동안은 어떤 반응도 그리지 않는다. 반응이 그려지는 길목은 `_apply`와 `_refresh`라 거기서 막는다
- ⚠️ 셸이 트리에 붙기 **전에** 멈춰야 한다. 배너는 `_ready`에서 곧바로 첫 문구를 찍으며 발화음을 낸다
- 그래서 `MainShell`에 배너를 멈추는 입구(`set_banner_suspended`)를 두고, 경로로 찾는다. `@onready`는 트리에 붙기 전에 비어 있다

### 리그

- `ShimejiView`에 `face`(표정)를 추가한다. 기본값 `NONE`이면 지금과 같다
- 가리키기용 팔 각도를 밖에서 줄 수 있게 한다(`point_l`, 왼팔에 더하는 각도)
- 시메지 쪽 동작은 바뀌지 않는다

### 대본

- 문자열은 `localization/translations.csv`의 `ONB_*`에 둔다
- 키 이름은 `ONB_B<비트 번호>_<내용>`이다. 예: `ONB_B1_HELLO`
- 이름표 문자열은 `ONB_SPEAKER_HAZEL`이다. 이름을 밝히기 전의 `???`는 번역하지 않는다
- 대사에 쉼표가 들어간다. 그 칸은 큰따옴표로 감싼다
- 근거는 Godot 문서 "Localization using spreadsheets"다. 쉼표·줄바꿈·큰따옴표가 든 칸은 큰따옴표로 감싸라고 적혀 있다
- ⚠️ 지금 CSV는 따옴표를 쓰지 않는 관례다. 이 관례는 여기서 깬다. 따옴표가 없는 기존 칸은 그대로 둔다
- `{이름}`은 `.format()`으로 채운다. 문장을 통째로 키로 둔다
- 지문이 동작과 소품으로 바뀌어 연출 순서가 대본의 절반이다
- ⚠️ 이전 판의 `data/onboarding.json`은 두지 않는다. 연출 순서는 비트별 코드로 짜고 문자열만 키로 뺀다
- `CompanionEngine`은 건드리지 않는다
