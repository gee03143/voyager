# UI 연출

어떤 화면에 어떤 연출이 들어가는지와 그 방향성. 트윈을 걸 때의 기술적 제약은 `docs/architecture/ui-animation.md`가 갖는다.

컴패니언 배너의 발화 연출은 이 문서가 아니라 `docs/specs/companion-banner-typing.md`가 갖는다.

## 동작

### 방향성

전 표면에 공통으로 적용된다. 새 연출을 추가할 때 이 기준을 통과시킨다.

- 연출은 조작에 응답한다. 화면이 정적이면 조작이 먹었는지 알 수 없다
- 조작의 결과는 순간이동하지 않는다. 움직여서 도착한다
- 물성을 표현하는 것이지 축하하는 것이 아니다. 완료를 반짝이게 하거나 튀게 만들지 않는다
- 거두는 데 시간을 쓰지 않는다. 나가는 것보다 들어오는 것에 시간을 쓴다
  - 다음 것이 그것을 기다려야 할 때의 이야기다
  - 거두기가 남을 움직이면 들어오는 것과 같은 시간에 간다. 즉시 거두면 남들이 순간이동한다
- 표현 수단은 투명도·높이·이동·채움 넷이다
- 시간과 이징은 표면마다 따로 정한다. 공통 규격표를 만들지 않는다
  - 위젯마다 크기와 성격이 달라 하나의 규격에 맞추면 오히려 어색해진다
  - 값은 F6에서 눈으로 맞춘 뒤 확정한다
  - 값 옆에 무엇을 보고 정했는지 한 줄을 같이 적는다
  - 감속은 물체가 도착해 멈추는 표현이다. 쓸어가는 연출에 걸면 움직임이 앞쪽에 몰려 즉시 바뀐 것처럼 보인다
- ⚠️ 도장의 튕김(`TRANS_BACK`)은 축하의 성격이다. 다른 연출로 번지면 `docs/README.md`가 금지한 성과 압박 쪽으로 기운다

### 콘텐츠 스왑 — 사이드바 nav로 화면을 바꿀 때

- 이전 화면은 연출 없이 즉시 물러난다
- 새 화면이 왼쪽에서 오른쪽으로 들어온다
- 들어오는 연출은 길게 잡는다. 여기가 이 앱에서 가장 큰 변화라 무게가 있어야 한다
- 방향은 언제나 같다. 어느 항목을 고르든 왼쪽에서 들어온다
  - 항목 위치에 따라 방향을 바꾸면 같은 조작에 매번 다른 움직임이 나와 오히려 혼란스럽다
- ⚠️ 이전 화면에 퇴장 연출을 붙이면 그것이 끝나야 새 화면이 시작되어 조작이 늦어진다

### 탭 전환 — 저널·기록 대시보드 안의 서브탭

- 콘텐츠 스왑과 같은 부품을 쓰되 방향은 다르다. 새 탭이 아래에서 위로 들어온다
- 방향은 표면마다 따로 정한다. 시간과 이징을 표면마다 정하는 것과 같은 이유다
- 콘텐츠 스왑보다 바뀌는 영역이 작으므로 시간도 그만큼 짧다
- 탭 패널은 한 번에 하나만 보이므로 세로로 쌓지 않고 한 자리에 겹쳐 둔다
  - 그 결과 지금 최소 높이만 차지하던 자유 일지와 그래프 탭이 영역을 채우게 된다
- 화면에 아직 없는 동안에는 연출하지 않는다. 셸의 진입 연출과 겹쳐 보인다

### 선택 표시 — 사이드바 nav와 서브탭

- 탭을 고르면 선택 표시가 즉시 바뀌지 않고 색이 쓸어 들어오며 차오른다
- 선택이 풀릴 때는 즉시 사라진다
  - 차오르는 동안 잠깐 아무것도 선택 안 된 것처럼 보인다
  - 사용자가 직접 누른 직후이고 차오르는 시간이 짧아 문제되지 않는다
- 방향은 자리마다 정한다. 지금 정해진 것은 둘이다
  - 사이드바 nav는 왼쪽에서 오른쪽으로
  - 서브탭과 그래프 모드 전환은 중앙에서 좌우로
- 시간은 그 탭이 여는 패널의 진입보다 짧다. 버튼이 먼저 확정되고 화면이 뒤따라온다
- 채움 색은 지금 선택 상태가 쓰는 색을 그대로 쓴다. 테마에서 선택 색을 바꾸면 채움도 따라간다
- 글자가 진해지는 것은 이미 테마가 하고 있다. 새로 만들지 않는다
- ⚠️ 그래프 모드 전환은 여는 패널이 없어 서브탭의 정의에 맞지 않는다. 가로로 늘어선 겉모습이 같아 함께 넣었다

### 할 일 행

- 새 행은 높이가 펼쳐지며 스며든다
- 지워지는 행은 접히며 사라진다
- 아래 행들은 밀려 따라온다. 행마다 따로 움직이지 않고 컨테이너 배치를 탄다
- 체크한 행은 체크된 모습으로 제자리에 잠시 머문 뒤 접혀서 완료 섹션으로 옮겨간다
  - 체크됐다와 정리됐다를 두 박자로 나눠 보여준다
  - 완료 섹션이 접혀 있으면 옮겨갈 자리가 안 보이므로 그냥 접혀 사라진다
- 연달아 체크하면 머무는 시간이 겹친다. 앞 행은 머무는 것을 그만두고 곧바로 옮겨간다

### 일지 문서 목록 — 자유 일지 탭의 왼쪽

- 문서를 고르면 그 행이 세로로 두꺼워지고 잉크 워시 배경이 같은 시간에 스며든다
  - 두께와 색이 한 번의 움직임으로 읽힌다
  - 채움은 쓰지 않는다. nav는 뒤이어 콘텐츠가 들어오니 상태를 대표하지만 문서 행은 대표할 것이 없다
- 이전에 고른 행은 즉시 되돌아가지 않고 새 행과 같은 시간에 교대한다
- 선택은 항상 하나라 한 행이 두꺼워진 만큼 다른 행이 얇아진다. 목록 전체 높이는 변하지 않는다
- 새 문서는 높이가 펼쳐지며 스며들고, 지워지는 문서는 접히며 사라진다. 할 일 행과 같은 어휘다
- 그룹을 접으면 그 안의 행들이 각자 자기 높이를 동시에 접는다
  - 순서를 어긋내지 않는다. 문서가 많은 그룹에서 조작 하나에 대한 응답이 늘어진다
- 접기는 펼치기보다 짧다. 시야에서 치우려는 조작이다
- 목록을 다시 그리는 나머지 경로는 연출 없이 즉시 반영한다
  - 필터 전환은 행 몇 개가 드나드는 게 아니라 목록 구성이 통째로 바뀐다
  - 제목 반영과 그룹 이름변경·삭제는 사용자 시선이 목록에 없다

### 습관 체크

- 누른 칸이 색으로 채워진다
- 칸이 살짝 커졌다 돌아온다
- 주간 달성도 링이 이어서 차오른다
- 누른 결과가 칸에서 끝나지 않고 그 주 전체에 어떻게 기여했는지까지 이어진다

### 그래프 막대

- 막대가 즉시 그려지지 않고 아래에서 위로 차오른다
- 왼쪽 칸부터 차례로 시작한다. 한 칸의 두 막대는 함께 시작한다
  - 두 막대가 맞붙어 있고 목표 높이가 달라, 시작을 어긋내도 파도로 안 읽힌다
- 차오르는 속도는 고정이다. 축 끝까지 채우는 시간이 기준이고 절반 높이는 그 절반이 걸린다
  - 먼저 시작한 막대가 먼저 끝나지는 않는다
  - "큰 것이 느리게 움직여야 무겁게 느껴진다"를 한 화면 안에서 적용한 것이다
  - 픽셀이 아니라 축 높이 비율이 기준이라 창 크기가 연출 길이를 바꾸지 않는다
- 칸 간 시작 지연도 고정이다. 다만 시작 구간이 상한을 넘으면 그 안에 압축한다
  - 칸 수가 모드마다 다르다. 주 7칸, 년 12칸, 월 28~31칸
  - 압축이 걸리는 건 월 모드뿐이다
- 값이 0인 막대는 원래 그리지 않으므로 차오를 것도 없다
- 차오르는 것은 사용자가 이 화면에서 한 조작에 응답할 때뿐이다
  - 모드 전환과 기간 이동
  - 그래프가 화면에 나타날 때. 탭을 열거나 기록 화면으로 돌아올 때
  - 활동 로그 변경은 다른 자리의 결과가 흘러들어온 것이라 즉시 반영만 한다
- 화면에 들어오는 경우에는 잠깐 기다렸다 시작한다. 패널이 들어오는 연출과 겹치지 않게 한다
  - 이미 보이는 상태에서의 갱신은 기다리지 않는다
- 차오르는 도중에 또 갱신되면 버리고 처음부터 다시 차오른다
  - 축 최대값이 매번 다시 잡히므로 지금 높이의 의미가 달라진다. 이어갈 수 없다
  - 연타하면 끝까지 못 볼 수 있으나 완화 장치는 두지 않는다

### 팝업 — 마감일 선택, 그룹 편집

- 창은 즉시 뜬다
- 창 안의 내용이 스며들며 자리를 잡는다
- ⚠️ 창 테두리와 배경은 즉시 나타난다. 그 순간이 거슬리면 창 스타일박스를 비우고 내용 쪽이 배경까지 그리게 하는 방법이 있다

## 범위 아님

- **미니 위젯 전환** — OS 창의 크기와 플래그가 바뀌는 일이라 여기서 정한 어휘가 닿지 않는다. `Screen`의 몫으로 따로 다룬다
- **팝업 창 자체의 연출** — `Window`는 `CanvasItem`이 아니라 투명도도 크기 배율도 없다
- **이전 화면의 퇴장 연출** — 조작감을 해쳐서 넣지 않기로 했다
- **리스트 행의 개별 이동** — 높이와 투명도로 처리한다. 행마다 래퍼를 두는 비용에 비해 얻는 게 적다
- **공통 시간·이징 규격표** — 표면마다 따로 정한다
- **기록의 목록들** — 노트 스트림, 오늘의 집중 목록, 하루 타임라인. 할 일과 일지에서 만든 형태를 옮기면 되지만 이번엔 안 한다
- **일지 탭의 편집기** — 문서를 고를 때 오른쪽 제목·본문이 갈아끼워지는 연출. 목록을 끝낸 뒤에 얹는다
- **감사·무드 탭** — 같은 저널 대시보드 안이지만 목록의 성격이 달라 따로 정한다
- **죽은 경로의 연출** — `Notice`, `PopupFrame`, `World.tscn` 계열은 현재 셸에서 도달할 수 없다
- **컴패니언 배너의 발화 연출** — 별도 spec에서 이미 구현됐다
- **모션 줄이기 옵션** — 요구가 없다
- **할 일 좌측 레일의 선택 표시** — 같은 이동 성격이지만 이번엔 뺐다. 허전해 보이면 그때 넣는다
- **무드 레벨 선택의 선택 표시** — 장소 이동이 아니라 값 고르기라 차오름의 은유가 맞지 않는다
- **글자 굵기 변화와 `SELECTED` 표식** — 레퍼런스에 있지만 넣지 않는다

## 메커니즘 영향

- 할 일 목록의 갱신 구조를 바꿨다. 행을 파괴·재생성하지 않고 `Todo`로 키를 잡아 재사용한다
  - 전에는 체크·추가·삭제 어느 것이든 목록 전체가 파괴되고 다시 만들어졌다
  - 움직여야 할 행이 같은 프레임에 사라지므로 연출을 걸 자리가 없었다
  - 재사용하면 이전 순서가 남으므로 정렬은 매번 다시 잡아야 한다
  - 같은 할 일이 다른 그룹으로 옮겨갈 수 있으므로 시그널도 매번 다시 묶는다
- 습관 목록의 갱신 구조는 안 바꿨다. 셀 체크가 행을 파괴하지 않는다
- 콘텐츠 영역·탭 콘텐츠·습관 칸에 래퍼 `Control`이 필요하다. 전부 코드에서 만들어 씬 편집은 없다
- 선택 표시는 버튼의 배경 스타일박스를 코드에서 비우고 채움 레이어가 대신 그린다
  - 테마 파일은 고치지 않는다. 채움이 기존 선택 스타일박스를 복제해 쓰므로 테마가 단일 출처로 남는다
  - 채움을 켤지는 버튼 묶음마다 고른다. 값 고르기 성격의 묶음에는 안 걸린다
- 일지 문서 목록의 갱신 구조를 바꾼다. 할 일에서 한 것과 같은 형태다
  - 문서 행은 문서 id, 그룹 헤더는 그룹 id, 날짜 헤더는 제목 문자열로 키를 잡아 재사용한다
  - 헤더까지 재사용하는 이유는 접기 조작이 헤더 위에서 일어나기 때문이다
  - 헤더가 다시 만들어지면 호버 상태가 리셋되어 이름변경·삭제 버튼이 깜빡인다
  - 목록을 다시 그리는 여덟 경로 전부가 재사용을 타야 한다. 연출이 없는 경로도 행을 파괴하면 안 된다
- 그래프 막대는 노드가 아니라 그림이다. 차트가 막대마다 노드를 두지 않고 한 번에 그린다
  - 지금까지처럼 노드에 트윈을 걸 수 없다. 경과 시간 하나를 트윈하고 그릴 때 칸마다 제 진행률을 계산한다
  - 이 코드베이스에서 처음 쓰는 방식이다
- 그래프가 화면에 나타나는 것을 알아야 한다. 지금은 보이는지 여부를 신경 쓰지 않는다
- 저장 파일·스키마·시그널 배선·autoload 변경은 없다
