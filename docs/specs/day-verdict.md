# 하루 판정

유저가 자기 하루에 이름을 붙여 헤이즐에게 건넨다. 판정한 날이 쌓이면 헤이즐과 숲에 대한 사실이 열린다.

- 왜 하는가 — `docs/README.md`의 "하루 판정"
- 헤이즐이 왜 판정을 받는가(로어) — `docs/companion-persona.md` §2
- 이 문서 — **어떻게 동작하는가**

⚠️ 2026-10-02 논의에서 방향만 정해졌다. 정하지 못한 것은 아래 "미정"에 모았다. 미정 항목을 이 문서의 다른 절에 결정처럼 옮겨 적지 않는다.

## 동작

### 판정

- 판정의 대상은 기분이 아니라 **오늘을 어떻게 보냈는가**다
- 기분은 통제할 수 없는 날씨다. 판정은 그 날씨 속에서 오늘을 어떻게 보냈는지를 유저가 스스로 정하는 것이다
- 무드 기록(`mood.json`)과 별개의 기록이다
- 선택지 몇 개와 직접 적기로 받는다
- 선택지 문구 초안은 `잘 쥐고 보낸 날` / `버틴 날` / `흘려보낸 날` / `(직접 적는다)`다. 확정이 아니다
- 헤이즐은 어떤 판정에도 같은 온도로 받는다. 판정 내용에 따라 반응 톤이 바뀌지 않는다
- **한 번 정하면 끝이다.** 판정은 고치지 않는다. 트렁크에 넣으면 끝이라는 무게가 있다(2026-10-02 유저 결정)

### 판정 간격 — 날짜에 묶지 않는다

- 판정은 달력 날짜에 묶이지 않는다. 마지막 판정에서 **6시간**이 지나면 다음 판정을 받는다
- 판정 하나가 하루 하나다
- 자정을 넘겨 판정해도 된다. 지난밤을 놓쳤으면 아침에 판정해도 된다
- 간격을 둔 이유: 몇 시간 안에 하루를 연달아 판정할 일은 없다. 6시간은 3~6시간 범위의 위쪽 끝이다. 짧을수록 하루에 여러 번 판정해 해금을 당길 수 있다(3시간이면 하루 최대 8번)
- 시간 간격은 홈의 상태를 정할 뿐 유저에게 보이지 않는다. 남은 시간을 세어 보이지 않는다

### 판정 장면

- 홈에서 부르면 헤이즐이 걸어 들어와 수첩을 펴고 이름을 묻는다
- 선택지는 이름 셋, `(직접 적는다)`, `...나중에요`다
- `...나중에요`를 고르면 헤이즐은 물러나고 판정은 남지 않는다. 동의하지 않고 문만 열어둔다(페르소나 §4)
- `(직접 적는다)`는 이름 입력 칸이 뜬다. 최대 20자다. 비워두면 `...나중에요`와 같다
- 고르면 헤이즐이 받아 적고, 그 장을 접어 방 구석의 트렁크에 넣고 나간다. 트렁크는 로어의 곳간이다(페르소나 §2)
- 홈이 열려 있는 사이 판정이 이미 들어갔으면, 헤이즐은 벌써 넣어뒀다고 말하고 나간다
- 셸을 닫으면 중단이다. 받아 적기 전에 중단되면 판정은 남지 않는다

### 계기 — 홈

- 특정 시각을 강조하지 않는다. 시각에 맞춘 알림이나 몸짓을 두지 않는다
- 판정을 받을 수 있으면 홈에 `오늘은 아직 이름이 없어요`와 `헤이즐에게 말하기` 버튼이 보인다
- 홈의 문구는 헤이즐의 목소리가 아니라 중립 UI 언어다(페르소나 §5 "목소리의 경계")
- 버튼을 누르면 헤이즐 부르기가 일어난다. 대화는 곧장 판정으로 열린다
- 판정 간격 안이면 마지막으로 붙인 이름과 그 날짜(오늘·어제·월/일)가 보인다. 버튼은 없다
- 홈을 보는 동안 간격이 지나면 1분 안에 버튼이 돌아온다

### 홈 — 최근 판정과 총 개수 (2026-10-02 유저 결정)

- 판정이 하나라도 있으면 판정 카드 아래에 카드가 하나 더 보인다
- 최근 판정 7개를 도장으로 나란히 찍는다. 왼쪽이 오래된 것, 오른쪽이 최근이다
- 날짜가 아니라 판정 단위다. 판정하지 않은 날이 빈칸으로 남지 않는다
- 도장 아래에 그 판정의 날짜(월/일)가 작게 붙는다
- 도장은 종류마다 글자 하나만 다르다. 이름 셋은 `쥠` / `버` / `흘`이다
- 색·굵기·크기는 모든 종류가 같다. 도장 사이에 위아래가 없어야 판정이 점수로 읽히지 않는다
- 직접 적은 이름은 글자 대신 연필을 그린다
- 도장에 마우스를 올리면 이름과 날짜가 보인다
- 도장은 손으로 찍은 것처럼 조금씩 기운다. 같은 판정은 늘 같은 각도다
- 그 아래 `이름 붙인 날 N일`이 보인다
- 선으로 잇지 않는다. 해금까지 남은 수는 보이지 않는다(위 "범위 아님")
- 검토하고 고르지 않은 형태: 이름 목록 7줄(흐름이 한눈에 안 들어온다), 종류별 개수(성적표처럼 읽혀 정직한 판정을 막는다)

### 로어 해금

- 해금은 **판정한 날 수**로 연다. 친밀도(만난 날 수)와는 다른 카운터다(페르소나 §6)
- 판정 내용은 보지 않는다. `흘려보낸 날`도 `잘 쥐고 보낸 날`과 똑같이 하루로 센다
- 정직한 판정이 손해가 되지 않게 하려는 것이다
- 연속 기록이 없다. 판정하지 않은 날은 세지 않을 뿐이다
- 카운터는 줄지 않는다
- 해금되는 날에는 판정 장면 끝에 한 박자가 더 있다. 헤이즐이 두 문장 이하로 그 사실을 말한다
- 같은 날 방에 그 사실을 나타내는 물건이 하나 놓인다. 물건은 남는다
- 방의 물건을 누르면 그때 들은 말을 다시 볼 수 있다
- 말은 한 번 지나가고 물건은 쌓인다. 놓친 사실을 다시 볼 길이 물건이다

## 범위 아님

- 판정의 점수화·평균. 성과 압박 금지(README "하지 않는 것")
- 판정을 오르내리는 선으로 그리는 것. 자기 판정이 점수가 되고 과거의 자신과 비교하게 된다(페르소나 §4 금지 3번)
- 해금 예고와 진행도 표시. `다음 해금까지 N일` 같은 표시를 두지 않는다
- 해금으로 앱 기능을 여는 것. 열리는 것은 세계에 대한 사실뿐이다(페르소나 §6)
- 판정을 시각 기반 알림으로 재촉하는 것

## 메커니즘 영향

### 저장 (2026-10-02 합의)

- 새 저장 파일 `verdict.json`. 저장 파일이 7개가 된다
- 모델 `DayVerdict`(`scripts/data/day_verdict.gd`). 감사 일지(`gratitude.gd`)와 같은 모양이다
- 항목은 `{id, ts, kind, text}`다
- `kind`는 `held` / `endured` / `drifted` / `custom`이다. 선택지는 문구가 아니라 종류로 저장한다 — 문구를 고치거나 옮겨도 지난 판정이 그대로 읽힌다
- `text`는 `custom`일 때만 쓴다
- `id`는 `IdGen`이다. 기억 축이 판정을 참조할 수 있어 일지·무드·감사와 같은 기준을 따른다
- 날짜 필드는 없다. 화면에 보일 날짜는 `ts`에서 계산한다
- 고치는 함수를 두지 않는다. 한 번 정하면 끝이다
- 판정 간격(`GAP_SEC`, 6시간)과 받을 수 있는지(`can_judge`)는 모델이 갖는다. 지금 시각은 부르는 쪽이 넘긴다
- 해금 진행은 저장하지 않는다. 판정 개수(`count`)에서 센다
- 저장 정책은 save-on-change다. 판정은 드물어 디바운스하지 않는다
- 샌드박스의 파일 목록(`sandbox.gd`의 `SAVE_FILES`)에도 더했다
- ⚠️ 새 `class_name`은 에디터가 다시 훑기 전까지 전역 목록에 없어 파스 단계에서 안 잡힌다. `Save`와 홈은 `preload`로 직접 가리킨다(`save.gd`의 `SANDBOX`와 같은 방식)

### 부르기 배선

- 홈 패널이 `verdict_requested`를 쏜다. `MainShell`이 같은 이름으로 다시 쏘고 시메지 루트가 받는다
- 홈은 패널 풀에 하나만 있어 `MainShell._ready`에서 한 번만 잇는다
- 시메지 루트의 `_call_hazel(verdict)`가 부르기 재생기에 판정 여부를 넘긴다. 방을 눌러 부를 때는 지금처럼 대화 라우팅이다
- 부르기 재생기(`hazel_call.gd`)의 `start(shell, main_shell, verdict)`가 판정이면 `_play_verdict`를 재생한다
- 대화 모드의 `ask_name`이 글자 수 상한을 인자로 받는다(기본 12, 판정의 직접 적기는 20)

### 홈 패널

- `scenes/home/HomeView.tscn` + `scripts/home/home_view.gd`. `MainShell.CONTENT_SCENES`의 0번이다
- 최근 판정 카드는 씬이 아니라 `home_view.gd`가 코드로 만든다. 도장 하나는 `scripts/home/verdict_stamp.gd`가 그린다
- 도장 글자는 번역 키(`VERDICT_STAMP_*`)다. 언어마다 한 글자를 고른다
- 이전까지 0번은 비어 있었다

### 아직 없는 것

- 방(`hazel_room.gd`)에 해금 물건을 그리는 자리. 해금 사실이 정해진 뒤다

### 테스트

- 6시간 간격은 샌드박스에서 개발자 콘솔 `date +1`로 넘긴다. `DateUtil.now_unix()`가 옮긴 날짜를 따른다

## 미정

- 판정 선택지의 최종 문구와 개수
- 해금할 사실의 목록·순서와 각 사실의 물건·대사 쌍. 초안만 있고 확정이 아니다
- 해금 간격(몇 번째 판정에서 열리는가)
- 방을 눌러 헤이즐을 부를 때도 판정이 선택지로 있는지
- 지금의 대화 라우팅(`COMPANION_TALK_*`)을 판정 대화와 어떻게 합칠지. README "대화 라우팅 템플릿"의 ⚠️ 참고
- 기억 축이 판정한 날을 재료로 쓸지. 예: 유저가 힘든 날을 판정했을 때 예전에 이름 붙인 날 하나를 꺼내 오는 것. 제안만 있었다
