# Voyage

Godot 4.6 기반 self-care 저널 컴패니언 앱. 할일·습관·뽀모도로·저널 같은 일상 생산성 도구를 하나의 컴패니언이 지켜보고 반응하는 형태로 엮는다.

## 포지셔닝

Finch류 self-care 컴패니언에 가깝다. Chill with You 같은 "co-work 상주형"(긴 작업 세션 동안 곁에 머무르는 배경 존재)과는 다르다 — Voyage는 **다이어리형**이다: 하루 여러 번, 짧게 열고 닫는 체크인 중심. 이 차이가 앱 셸 구조(배경 월드 없음, 고정 배너)와 컴패니언 상호작용 밀도(옅고 길게가 아니라 짧고 진하게)를 결정한다.

## 할 수 있는 것

**생산성 도구**
- 할일: 다중 그룹, 마감일, 정렬, 드래그 정렬
- 습관 트래커: 요일 단위 반복, 주간 달성도
- 뽀모도로 / 일반 타이머 / 알람

**기록 도구** (다이어리)
- 활동 로그, 캘린더 히트맵, 통계
- 자유 일지, 무드 기록, 감사일기

**컴패니언**
- 생산성 도구의 실행 결과에 반응한다: **활력**(할일·습관 완료), **함께 있음**(뽀모도로/타이머 세션)
- 기록 도구의 내용을 기억하고 되짚어준다: **기억**(저널·감사일기·무드 — 과거 기록을 인용하며 되돌려줌)
- 뽀모도로 로그는 생산성 측정이 아니라 **reflection의 객관적 근거**로 쓰인다 — 자기보고(저널)가 그날 기분에 왜곡되기 쉬운 걸 보정하는 재료
- 집중 안 됨 / 심심함 / 무드 안 좋음 같은 상황에서, 컴패니언이 공감 한 줄 + 객관식 선택지로 기존 도구(저널 쓰기, 짧게 집중하기 등)로 안내한다 — 자유 대화 AI 아님

## 하지 않는 것

- **유저 간 실시간/비동기 소통**: 편지·메시지·랭킹 등 유저 간 연결 기능 없음. 연결은 유저-컴패니언 관계로 한정.
- **리더보드·랭킹·소셜 비교**: 다른 유저와 비교하는 어떤 지표도 노출하지 않음.
- **성과 압박**: 스트릭 강제(끊기면 페널티), 완료율 점수화, 미완료/0세션/낮은 무드에 따라 컴패니언 반응 톤이 나빠지는 것 — 전부 금지. 컴패니언은 항상 같은 온도로 반응한다.
- **자유 대화 AI**: 컴패니언은 정해진 트리거·문장·선택지 기반으로만 반응(대화 라우팅 템플릿). 개방형 챗봇이 아니며, 고민을 대신 풀어주지 않고 기존 도구로 안내만 한다.
- **상시 상주형 co-work 컴패니언**: Chill with You류의 "곁에서 계속 함께 있는" 모드는 다루지 않음. Voyage는 짧게 열고 닫는 다이어리형이다.

## 앱 셸

배경 월드 없음, 순수 UI. 좌측 사이드바(도구 진입) + 상단 **고정 배너**(컴패니언 상주 영역) + 콘텐츠 영역(패널 스왑).

![앱 셸 와이어프레임](docs/assets/app-shell-wireframe.svg)

고정 배너는 사이드바와 같은 성질 — 어떤 도구를 열어도 안 바뀐다. 이 구조는 포지셔닝(다이어리형 vs co-work 상주형)에서 직접 도출된다. 상주형이었다면 배경 월드 자체가 "항상 곁에 있음"을 담당했겠지만, 다이어리형은 짧게 열고 닫으므로 그 역할을 고정 배너가 대신 맡는다.

사이드바 하단엔 진행 중인 뽀모도로/타이머가 **상시 표시**된다 — 어떤 패널을 열어도 타이머는 계속 보인다.

이와 별개로, 창을 최소화했을 때를 위한 **always-on-top 컴패니언 모드**가 있다. 다만 여기서 되는 건 타이머 표시뿐이다 — 컴패니언과의 상호작용, 저널 작성, 기록 열람 같은 기능은 전부 메인 셸 안에서만 이뤄지고, 컴패니언 모드에선 불가능하다. 그리고 이 모드는 **집중 세션이 진행 중일 때만** 의미가 있으므로, 그 맥락 밖에서 진입할 이유가 없다 — 트리거도 그 범위로 한정한다.

데스크톱에서는 화면 폭 여유로 우측에 "한눈에 보기" 패널(주간 무드 그래프, 최근 저널 스니펫 — 위 이미지의 점선 영역)을 추가할 수 있으나, 상세 편집은 항상 가운데 패널에서만 — 한눈에 보기와 하기의 역할을 섞지 않는다.

## 컴패니언 설계

### 3축 반응 매핑
컴패니언이 뭘 보고 뭐라고 말하는지를 정하는 규칙표. 세 축은 **시간 범위**로 구분된다 — 활력은 **오늘 하루치**, 함께 있음은 **지금 이 순간**, 기억은 **과거 전체**. 축마다 (1) 보는 데이터 → (2) 계산 → (3) 표현, 세 단계로 이어진다. 모든 축은 **신규 데이터를 만들지 않고 기존 도구의 결과를 다르게 읽는다.**

**활력 (vitality) — 오늘 뭘 했는지**
- 보는 데이터: 오늘 할일 완료 개수, 습관 체크 여부
- 계산: 완료 비율/개수 (정확한 공식은 구현 시 결정 — 핵심은 "완료=활력↑")
- 표현: 완료 많음 → 활기찬 포즈 + "오늘 다 해냈네!" / 완료 없음 → **평소와 똑같이 차분한 포즈** + "오늘은 좀 쉬어가는 날인가 봐" (절대 "왜 아무것도 안 했어" 식으로 안 감)
- **핵심 원칙**: 활력이 낮다 ≠ 컴패니언이 실망한다. 활력은 컴패니언의 겉모습(포즈·생기)에만 영향을 주고, 감정이나 태도엔 영향을 안 준다 — "하지 않는 것"의 성과 압박 금지 원칙이 코드로 구현되는 지점.

**함께 있음 (presence) — 지금 같이 있는지**
- 보는 데이터: 뽀모도로/타이머의 현재 상태(진행 중 / 방금 종료 / 없음)
- 계산: 위 세 상태 중 하나로 분기
- 표현: 진행 중 → 조용히 옆에서 집중하는 애니메이션(말 걸지 않음, 방해 안 하는 게 목적) / 방금 종료 → "수고했어, 뭐 하고 있었어?" + 세션 로그(몇 분 집중했는지)가 저널 작성 시 참고 자료로 노출 / 없음 → 평소 대기 상태, 재촉 없음
- **기억 축과의 연결**: 세션 종료 로그는 그 자리에서 소비되고 끝나는 게 아니라, 나중에 저널 쓸 때 "아까 18분 집중했었네" 하고 다시 등장한다 — 뽀모도로 로그가 기억 축의 재료로 넘어가는 구조. ("뽀모도로 = reflection의 객관적 근거" 원칙이 실제로 작동하는 지점.)

**기억 (memory) — 예전에 뭐라고 했는지**
- 보는 데이터: 과거 저널·감사일기·무드 기록(오늘 게 아니라 지난 기록)
- 계산: 저장된 기록 중 하나를 다시 꺼내옴(랜덤/조건부 선택 기준은 구현 시 결정)
- 표현: "그러고 보니 저번주 화요일에 '면접 결과 기다리는 중'이라고 적었었잖아, 어떻게 됐어?" 같은 식으로 컴패니언이 먼저 언급하며 대화를 연다. 무드가 안 좋았던 기록을 꺼낼 땐 표정만 살짝 다운되고 대사 톤은 동일하게 다정함(점수화 금지 원칙 유지 — "그날 기분 -1점" 같은 건 없음)
- **핵심 원칙**: 컴패니언이 "기록 보관함"이 아니라 "기록을 기억하는 존재"로 느껴져야 한다. 지난 일지를 그대로 보여주는 게 아니라, 컴패니언이 먼저 그걸 언급하며 대화를 여는 방식이어야 한다.

**공통 원칙 (세 축 전부 적용)**: 어떤 입력값(미완료·0세션·낮은 무드)이 와도 컴패니언의 반응 **톤**은 바뀌지 않는다. 바뀌는 건 표현(대사 내용)뿐이다. 이 원칙이 깨지는 순간, 컴패니언은 "하지 않는 것"에서 금지한 성과 압박 장치로 되돌아간다 — 새 반응을 추가할 때마다 이 기준으로 검토할 것.

### 대화 라우팅 템플릿
자유 대화 AI가 아니라, 트리거별로 콘텐츠를 갈아 끼우는 반(半)스크립트 시스템.

흐름: **트리거**(집중 안 됨 / 심심함 / 무드 안 좋음) → **공감 한 줄** → **객관식 2~4개** → **후속 반응**(맥락 기억).

- 옵션엔 **"그냥 쉬기"가 항상 포함**된다 — 전부 "뭔가 하기"로만 구성되면 은근한 성과 압박이 된다.
- 컴패니언의 역할은 고민을 "풀어주는" 것이 아니라 기존 도구(저널 등)로 "안내하는" 것으로 한정한다 — 상담 챗봇화 방지.
- 트리거·문장·옵션은 코드가 아니라 콘텐츠 데이터로 관리한다(새 트리거 추가가 코드 수정 없이 가능해야 함).

### 비주얼
컴패니언의 구체적 형태(종·이름)는 미확정. 스타일 방향만 확정: **캐주얼풍 2D 스타일라이즈드 그래픽**. 아이콘이 아니라 바닥선 있는 "무대"(작은 서식지 배경 존)에 서 있는 형태로 배치 — 캐릭터가 UI 요소가 아니라 그 안에 사는 존재로 읽히게 한다. 포즈는 최소 4종: 기본 / 반응(말할 때) / 기쁨(완료 등) / **차분**(0세션인 날에도 다정한 톤 — 3축 원칙의 시각적 구현). 이름은 화면에 상시 노출한다(구체 이름 미정).
