# Voyage 로드맵

> 현재 구현 상태(`implementation.md`)에서 목표 상태(`README.md`)까지 가기 위한 작업 목록. 순서는 의존관계 기준 — 주차·소요기간은 배정 안 함(착수 전 가늠 필요).

## 결정 사항 (2026-07-29)
- **활동 태깅(`ActivityVocab`) 유지**: `activity_select.gd`("지금 뭐 하는지" 선택)와 `record_view.gd`의 활동 표시는 그대로 둔다. **어휘 해금·편지·편지 도감만 삭제** — 이 셋은 애초에 `ActivityVocab.SUBJECTS`(태그 목록)와 별개로, 잠금 해제 게임 요소(`Lexicon`)와 편지 UI(`scripts/letter/` 대부분)에만 걸려 있어서 태깅 자체는 안 다침.
- **always-on-top 컴패니언 모드: 존재하되 타이머 전용으로 한정**: `CompanionMode.tscn`은 그대로 유지하고, **거의 모든 기능이 불가능하고 타이머 표시만 담당**한다 — 확인해보니 지금 코드가 이미 이 범위 그대로(링 진행도·시간·복귀 버튼뿐, 컴패니언 상호작용·저널·기록 열람 없음)라 별도로 깎아낼 코드는 없음. 컴패니언 상호작용·저널 작성·기록 열람은 전부 메인 셸(사이드바+배너+콘텐츠) 안에서만. **트리거도 "집중 세션 진행 중"으로 한정** — 세션 없을 때 들어가봤자 보여줄 게 없으므로(아래 B번 확인 사항 참고). 셸 안 사이드바의 배·패럴랙스는 별개 — 이건 B번에서 임시로 재사용됐다가 F번에서 컴패니언+무대로 교체될 예정(아래 B·F 참고).
- **`letters`/`lexicon`/`voyage_distance` 데이터: 죽은 필드로 방치**: 스키마 정리·마이그레이션·버전 bump 안 함. 편지 UI를 걷어내면 이 필드들에 대한 활성 쓰기는 대부분 자연히 없어지지만(예외: 아래 참고), 데이터 모델 클래스(`Lexicon`/`LetterArchive`)·`Save`의 필드 자체는 그대로 남겨둠.
  - 예외: `voyage_distance`는 `CompanionMode.gd`가 계속 적립함(위 결정과 연결 — 컴패니언 모드를 그대로 두기로 했으니, 그 안의 배 애니메이션이 쓰는 `voyage_distance`도 계속 살아있는 값임. "죽은 필드"가 아니라 "컴패니언 모드 전용으로 계속 쓰이는 필드"로 정정).
- **감사일기·무드 기록: 구현 방식 추후 결정**. 지금은 "이런 게 필요하다"는 계획만 로드맵에 남기고, 데이터 모델·UI는 착수 시점에 다시 논의.

## 보류
- **`CompanionMode`(별도 always-on-top 창) 자체의 배·패럴랙스 비주얼**: 사이드바 쪽과 별개 사안 — 이번 로드맵에서 안 건드리기로 했으니(위 결정 사항), 이 창 안의 비주얼을 나중에 교체할지는 그때 다시 논의.
- **마일스톤/업적 시스템**: 컨셉 유효(집중 통계 계속 쌓임), 데이터 소스를 항해 → 습관/저널/뽀모도로 통계로 교체 필요.
- **유저 간 연결 기능**: 편지 시스템이 담당하던 니즈. 필요 여부는 이번 로드맵 이후 재검토.
- **`voyage_panel.gd`(항해 통계 탭)**: 당장 손 안 댐(letters/lexicon과 같은 "방치" 취급) — `voyage_distance`가 `CompanionMode`에서 계속 쓰이는 한 이 탭도 자연스럽게 유효한 정보를 보여줌.
